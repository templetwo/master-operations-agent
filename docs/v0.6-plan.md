# V0.6 execution plan and acceptance gates

Requested 2026-09-20. Baseline: public commit `7451a72`, with frozen actual model runs at `dd40e9d`. This work follows the external reviews while preserving advisory-only scope, original evidence, and the release validator.

1. **Failure accounting.** Record the stage at which a run fails, distinguish input, provider, tool, candidate, voluntary refusal, and budget failures, and derive candidate rejection totals from those stages. Accept when tests distinguish the same schema error across input/tool/candidate boundaries and totals reconcile with case outcomes.
2. **Offline diagnostics.** Verify exported evidence, compare saved candidates with explicit case labels without calling the production oracle, and report missing/extra findings and checks separately from release acceptance. Any envelope normalization is an explicitly separate offline view. Accept when all historical comparison exports can be audited without modification, including refusal controls and malformed/tampered inputs.
3. **Complete policy guidance.** Spell out all existing check mappings, overrides, trend rules, numeric comparisons, evidence requirements, and uncertainty rules in a versioned optional guidance specification. Accept when independently authored examples cover the mappings and original policy/validator behavior remains unchanged.
4. **Controlled development experiment.** Preregister a four-arm experiment: unchanged prompt, output-contract guidance only, complete policy guidance only, both. Use the same DeepSeek alias, decoding settings, release policy, simulator revision, and paired development observations. Rotate arm order by case. Record all attempts, guard outcomes, usage, metadata, and source stability. Accept completion of a valid, honestly reported comparison, not any minimum model score. No automatic default-provider promotion follows.
5. **Independent holdout preparation.** A separate agent authors a private set without inspecting development responses. A different agent reviews labels and contract validity independently of `eligible()`. Freeze the reviewed corpus with hashes, a public protocol, preregistered thresholds, and an exposure record before any model evaluation. Accept a usable frozen artifact and review, not a claimed capability result. This is independent agent review, not independent controls-engineer approval. Keep holdout observations and labels out of public Git and out of tuning prompts.

Accounting, diagnostics, and policy agents own disjoint files. The coordinating agent builds the experiment runner, reviews integration, and performs final validation. Holdout author and reviewer work on separate turns after a slot becomes available. They do not author tuning prompts. No plant connection, write tool, fine-tuning, hardware purchase, or validator relaxation is part of this plan.

Validation includes the full implementation suite with the trusted simulator, real local HTTP tests, offline audits, one bounded cloud development experiment after its preregistration is committed, and independent review of the private holdout. Changes and receipts will be published on the existing public `main` branch after credential and publication checks. Historical receipt directories are immutable.
