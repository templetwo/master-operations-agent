Run three pairs in fixed order: unloaded, then immediately loaded. Maximum six completion attempts. Every completion uses the exact full policy-only system prompt, canonical public ENTRY, declared-order response schema, temperature 0, seed 0, 768 output tokens, 8192 context, thinking disabled, nonstreaming output and five-minute keep-alive. No observations or tool results are provided. The expected response is the original first tool request: `read_snapshot` with empty arguments. This tests protocol startup, not useful advice or abstention.

The production provider, campaign scripts, scored-request timeout and 60-second freshness limit stay unchanged. Stop the diagnostic after any invalid/incomplete reply, timeout, HTTP error, state mismatch or integrity failure. No retries or substituted pairs; preserve partial results. A timed-out server could continue computing after the client disconnects, so do not send a follow-up request after failure.

Before each unloaded member, inspect `/api/ps`. If another model is loaded, stop without eviction. If this exact Gemma is loaded, send its model-only unload request (`keep_alive:0`) and require a subsequent empty inventory. Verify the same digest and reported context before each loaded member. These commands control this local model's residency only, not plant state. At most three unload commands are possible; they request no completion. Leave the last successful member loaded under its normal five-minute expiry.

"Unloaded" means absent from the daemon's memory inventory, not cold OS file caches or rebooted hardware. Fixed ordering, identical prompt reuse, uncontrolled filesystem caches, system load and possible other clients are confounds. The loaded member can benefit from prompt caching as well as model residency. Record full request/response bytes, hashes, client elapsed time, daemon load/prompt/generation durations and available cache counters. Missing server fields remain missing, not zero. Nonstreaming timing is not time to first token. The daemon is trusted infrastructure, not externally attested.

Interpretation is fixed in advance. Require all six correct, completed first-tool replies and unchanged metadata/source. If any loaded member exceeds 20 seconds, a longer one-time warmup alone is not supported. If all unloaded members are also at or below 20 seconds, this sample does not show a need to enlarge the warmup. Otherwise propose, for a future separately registered configuration only, the smallest of 60 or 120 seconds that is at least 1.5 times the slowest unloaded member. If neither fits, or the run is incomplete, the result is inconclusive. This small-sample margin is an engineering choice, not a statistical reliability guarantee or permission to change scored-case budgets.

The result may motivate a separate registration; this task does not execute it or replace the failed campaign. No claim of model usefulness, operational readiness or safety follows from startup timing.
