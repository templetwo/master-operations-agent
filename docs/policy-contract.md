# Policy and output contract clarification

The optional constants in `moa/guidance.py` present the existing contract in two
separate experimental factors. `OUTPUT_CONTRACT_GUIDANCE` specifies the JSON
envelope and list constraints without supplying finding/check answers.
`POLICY_GUIDANCE` specifies the complete authored rule mapping without seeing a
case, case label, or expected output. Neither changes the default prompt, policy
hash, thresholds, validator, provider settings, or six-response budget.

This is a presentation change for a controlled experiment. It is not a new
policy revision. The experiment must record the actual system prompt and hashes
of the factor strings and retain the unmodified release decision.

The original policy already describes the trend-to-check mapping. The genuine
omissions are the full snapshot check mapping, the demo check replacement, and
the numerical rounding semantics. The clarification also makes explicit that
the window check union retains `continue_observation` when alarms are absent,
that historical quality suppresses all numerical window findings, and that all
five history references remain required even in that quality branch.

There is a small but real precision distinction: `history_findings()` compares
Python `round(difference, 6)` to thresholds for net and peak differences, while
the original prose only states the thresholds. A raw difference of 1.9999996
rounds to 2.0 and meets the warming threshold. Current controller output and
demo thresholds are not rounded. The experiment discloses this existing behavior
instead of changing it. A future policy revision could select different numerical
semantics, but it would need a new policy identity and independent review.

The mapping can produce combinations that require careful reading:

| Observation | Required behavior |
|---|---|
| No alarms, demo mismatch | `no_reported_alarms` remains, but `continue_observation` is replaced by the demo checks |
| No alarms, reliable window | `continue_observation` is retained and `compare_independent_measurement` is added |
| Quiet endpoints with an earlier reactor peak | `no_large_net_change` and `reactor_below_window_peak` can coexist |
| Unreliable historical sample, good latest snapshot | Snapshot findings remain; window findings are only `history_quality_gap` and `cause_unresolved` |
| Large negative feed change | It prevents `no_large_net_change`, but the catalog has no decreasing-feed finding |

The tests use manually authored expectation sets and numeric boundary examples,
not outputs generated by the baseline. They check that these examples match the
current implementation and that the two instruction factors stay separate.
They are implementation checks, not independent process truth or a holdout.

Exact set equality is the current release rule. Missing a warning, adding an
unsupported finding, adding an unnecessary check, and a malformed envelope are
different diagnostic failures even when all produce withholding. Exact policy
agreement alone does not establish usefulness beyond the deterministic baseline,
plant safety, generalization, or resistance to arbitrary hostile evidence. The
policy and these clarifications have no controls-engineer approval.
