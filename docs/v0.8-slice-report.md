## What is implemented

The separate `moa.stream` module consumes schema 1.2, `ess-u1-stream-v1`, adapter `ess-stream-v1`, and policy `lab-v2-deps`. It opens only fixed observation/configuration/operator filenames on the stream side. Read tools operate on detached validated memory. There is no provider or action executor in this path.

The Node observer copies named fields from `project(state, 'subject')`. The Python contract independently rejects unknown keys, incoherent clocks, invalid quality/value combinations, and mismatched configuration or registered source identity. BAD values are null. GOOD source quality is preserved when a configured-range check sets `derived.over_range`.

The new result includes a structural `unusable_measurements` array containing catalog ID, validated tag, fixed reason code, and fixed catalog text. Ordinary findings remain IDs. The `stream_id` binds the exact observation manifest, including simulator revision and model ID. It is an observation-contract identity, not a unique randomized physical-run identifier: Normal and its twin intentionally share it. Policy identity is exposed through `read_policy` and these receipts.

Each tag is its own declared failure domain; topology has not been reviewed. No readings are claimed to independently confirm each other. `--no-scoped-degradation` disables narrowing in this new path only. Legacy bad-quality expectations and lab-v2 remain unchanged.

The visible trend grid has 25 slots over 120 seconds. Its end advances every five seconds. The latest available sample at or before a grid instant is used only within the declared one-second sample period; an absent grid sample stays missing. No interpolation or stale backfill occurs. Between grid endpoints, current BAD quality immediately invalidates dependent trends. Instant alarm, output, quality and range checks use each one-second sample. The pure selection function is called each sample; its numerical trend evidence changes only on the grid cadence.

A gap longer than five seconds discards history. Duplicates, reversals, inconsistent sequence clocks and inline epoch changes are rejected. An explicit epoch transition resets history and resumes instant assessment. A new process refills history. Release checks the current accepted sequence and tick, seals the issued decision against in-process mutation, rejects reentrant state changes during publication, and checks live freshness before and after writing. This is a local API boundary, not OS filesystem confinement or protection against a privileged writer. Stream results are JSONL records; they do not add peb integration or a new evidence-chain guarantee.

## Corrections during implementation

Independent agent review reproduced an epoch race, mutable prepared-result bindings, success on an empty input stream, and unchecked initial sequence numbers. These were corrected in the new code. Review also found a reentrant-sink release error; publication now rejects state-changing reentrancy and checks freshness again afterward. Regression tests cover ordering, bound-result mutation, write failure, the grid cadence, quality scoping and read-tool argument restrictions.

An initial broader test attempt encountered the sandbox's loopback restriction. A later concurrent test run failed a legacy mocked campaign's completion assertion while implementation files were still changing. The captured traceback does not establish its exact cause. The subsequent frozen-source validation completed 173 tests with no skips or failures. No legacy test or expectation was edited to obtain that result.
