# Private synthetic holdout protocol

The private u1-v1 package contains 30 independently authored synthetic contract/policy cases: 24 usable windows and six intentional guards for the existing ess-u1-window-v1 contract. Broad coverage includes independent changes, interior extrema and net stability, precision-six thresholds, historical quality gaps, alarm combinations, and input-contract guards. These are not physically validated simulator trajectories, not controls-engineer-reviewed, and not plant trials. They provide no independent process truth or model capability score.

The package lives outside Git at `/Users/vaquez/.moa/holdouts/u1-v1`. This public document and the author/review receipts contain no observations, labels, case identifiers, or per-case results. The root/tuning role may receive only the package path, interface, counts, broad families, methodology, exposure limits, and hashes. Authoring did not inspect development cases, receipts, outputs, or tuning tests. The author did see eligibility implementation during a whole-file policy read; the capsule discloses this. There is no implementation-blind authoring claim. Expected sets were entered explicitly from prose rules and the assignment's precision-six convention; no production eligibility, Baseline, or model generated them.

The private `cases.json` contains inputs, explicit expected finding/check/evidence sets or guard rejection expectations, and rationales. `materialize.py` is a standalone Python-standard-library materializer. Its Python `materialize(case_id, now=None)` function returns an observation without labels; omitted `now` uses current UTC. Its CLI accepts `--case` and optional `--output`, refusing an existing output file. The private corpus supplies identifiers to the isolated evaluator; do not list them publicly. Each call has fresh opaque snapshot and history-epoch identities and fresh observation wall time, with frozen simulation values/timing retained and any intended guard applied. Synthetic source metadata is a declaration, not authentication. Do not publish generated observations.

The author freeze manifest hashes every authored package file except itself, with its own SHA256 recorded in the public capsule. A different reviewer must independently inspect private observations, manually specified expected sets, rationale, and materializer against the public contract/policy, without invoking production eligibility/Baseline for expected labels and without relying on an author checker. No author label checker is provided. The reviewer keeps detailed notes and corrections private, publishes aggregate findings and exposure information, and freezes reviewed final hashes before evaluation. Corrections require a new reviewed freeze; preserve the original author freeze as historical provenance.

An isolated evaluator must verify the reviewed freeze before any provider sees observations. Keep guard rejection, useful-response results, always-refuse negative-control results, deterministic baseline results, and actual provider results distinct. Preserve exact eligible-set checking and abstention handling under the public evaluation contract, without treating always-refuse behavior as useful task completion. Materialize immediately before each attempt; use a common validation clock where necessary for intentional time guards. Retain detailed transcripts and per-case diagnoses privately. Public reporting must state the evaluation mode, aggregate counts, hashes, overlap uncertainty, and all provenance/exposure limitations. A hash freeze is local integrity evidence, not external attestation. Any tuning role exposure to observations, labels, or per-case diagnoses invalidates a future unexposed-holdout claim for that role.

The reviewer previously implemented accounting and saw development tests, code and discussion. This is separate-agent review, not a wholly blinded reviewer or controls engineer. After deriving labels, the reviewer privately compared normalized process content with 36 inputs from the latest archived local/cloud development reports, representing 17 distinct normalized inputs. No exact overlap was found. This does not establish semantic independence, new physical regimes, or cross-unit generalization. Detailed results remain private. The reviewer must not use the exposed holdout to tune the agent.

Before any holdout evaluation, the following acceptance rules are frozen in the private `review/preregistration.json` and its hash is included in the reviewed manifest:

- Primary gate: 24/24 exact released useful assessments, 6/6 correct input guards, and zero unexpected guard advisories. These are strict research regression thresholds, not industrial acceptance criteria.
- Secondary checks: 24/24 required-read completion and exact finding, check, and evidence sets; zero unsupported released content; evidence fidelity of 1.0 over released advice. With zero releases, fidelity is undefined and cannot pass. Diagnostic coverage and extra/missing IDs never change release decisions.
- Run both controls separately. The deterministic baseline must match all authored expectations. Always-refuse must yield 0/24 useful assessments and 6/6 guards. A baseline mismatch invalidates the comparison and requires private investigation, not changed labels to match the baseline.
- Freeze provider settings/identity, exact prompt, source revision and run count before evaluation. Score the first attempt for every case with fixed denominators. Provider errors, malformed answers, expiry, abstentions and budget exhaustion are failed useful attempts. An aborted campaign is incomplete, never passing. No selective retries or post-hoc exclusions.
- Keep transcripts and per-case diagnostics private. Any tuning-role exposure retires the unexposed-holdout claim for that role. Changes to thresholds, labels, materialization or evaluation require a new preregistration/freeze with the old record preserved.

No agent, deterministic baseline or model holdout evaluation has occurred. Construction and label-consistency checks are not evaluation results.
